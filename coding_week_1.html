Beat One · Lesson 1 — Programming in the AI Era

Is It Even Worth Building? And Where Do You Start?

Programming used to mean memorising syntax before you could solve anything. Now the durable skill is different: describe a problem clearly, let AI generate code, then run it, read what happened, and fix it. Today Maya decides the receipt problem is worth a tool — and picks the lowest-friction place to build it.

📖 The story so far Sunday, 8:10 p.m. Maya has just spent 55 minutes hand-totalling last month's candle receipts — and the number still feels wrong. She almost gives up. Then she reframes it: this is a task a computer does perfectly and instantly, and I no longer need to learn a whole programming language to get one. The question isn't "can I code?" It's "can I describe what I want clearly enough for AI to build it — and can I check the result?" First: where should she even type?

"Clean my receipts" is a wish, not an instruction. Thinking like a programmer means breaking a fuzzy goal into small, ordered, checkable steps — and predicting what each one should produce. The clearer the spec, the better the AI's code. Today Maya decomposes ReceiptTidy into pieces and grades her own prompt.

📖 The story so far Monday evening. Before typing a single prompt, Maya writes the job on paper: what goes in, what should come out, and every messy step between. Beat Three · Lesson 3 — Your First Program (Debug It)

Hit a Real Error — Read It, Then Fix It With AI

Errors are not the enemy; they're the program telling you exactly where it got confused. The durable skill isn't avoiding errors — it's reading the message calmly and feeding it back to the AI with context. Maya's first run threw an error. Let's decode it together.

📖 The story so far Tuesday, later. Maya hit Run and got a wall of red text ending in ValueError: could not convert string to float: 'Rs. 450'. Her instinct is to panic and delete everything. Instead she reads it: the code tried to turn a price into a number, but one price still had "Rs." stuck to it. The error even names the exact bad value. That's a clue, not a catastrophe.

Beat Four · Lesson 4 — From Script to Shipped (Make It Reusable)

From "It Worked Once" to "I Can Use This Every Month"

A script that runs once on one file is a demo. A tool works next month, on next month's file, without you rebuilding it. Shipping means making it reusable, saving a version, and testing it so future-you trusts it. It's a checklist, not a leap of faith.

📖 The story so far Wednesday. ReceiptTidy gives the right total on the messy sample. Maya could stop here — but she remembers she'll face this same chore every single month. So she asks the AI to make it reusable: take any filename, handle an empty file gracefully, and print a clear message instead of crashing. Then she saves a copy she can come back to. Work through the ship-prep checklist.

Make-it-reusable checklist

  • Ask AI to accept any filename, not just one hard-coded file
  • Handle the empty-file case with a friendly message, not a crash
  • Print the total and how many rows it skipped (so nothing hides)
  • Save the working version (a dated copy she can return to)
  • Run it once more on the real file, start to finish
  • Note the one thing she'd improve next time (a to-do, not a crisis)
🚀 ReceiptTidy is reusable. Next month is now a 10-second job. One trust-check left before she calls it shipped.
