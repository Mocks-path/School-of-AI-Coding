What Is an API? — the doorway between your idea and a working AI

Four hands-on activities. Decode the status codes an API answers with, sort the round trip into what you send and what comes back, tell who can call an API (your app or a no-code automation), then lock it in with a myth-vs-reality quiz. By the end, "API" stops being jargon and becomes the shortcut you reach for.

Match the status code to what it's telling you

Every time you call an API, it answers with a status code — a three-digit number that says how the request went. Learn the common ones once and an "error" stops being scary; it becomes a clue. Click a code on the left, then click the meaning on the right that fits it. A wrong match shakes red so you can try again.

💡 Plain-English promise: an API — Application Programming Interface — is just a doorway one program uses to ask another to do something. You send a request; you get back a response with a status code and (usually) some data. Master these six codes and half of "debugging" is already done.

Who's calling the API? — app or automation

APIs aren't only for coders typing commands. Almost anything can be the thing that calls an API — an app you build, or a no-code automation that wires services together. Either way, you never build the AI; you just send it a request. Study the two cards, then drag each example into the bucket it belongs to.

A

An app calling an API

Something you build — a website, a chatbot, or a script — sends the request itself and uses the response.

  • A chatbot that calls an AI model per reply
  • A website calling a maps or weather API
  • A script you run each morning
  • Your own tool asking an AI to summarize
N

An automation calling an API

A no-code tool calls the API for you, on a trigger or schedule — nothing to build.

  • A workflow that emails you on a new form
  • A scheduler that posts every day
  • A "when X happens, do Y" automation
  • A spreadsheet add-on that calls an AI
💡 The point: the API doesn't care who is calling. Your app, your script, or a drag-and-drop automation all send the same kind of request and read the same kind of response. You never build the AI — you just ask it. That's what makes APIs the shortcut from idea to working feature.
