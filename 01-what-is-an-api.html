Week 5 · Lesson 01 · AI APIs

The waiter between your app and everything else.

You've built pages, prompts and automations. But your app can't do everything itself — it can't check the weather, translate a sentence, or run a giant AI model on its own. So it asks something that can. The way one program asks another for help, and gets a clean answer back, is called an API. This lesson makes that word concrete: you'll watch a single request travel out and a response come back, read the language APIs speak (JSON), learn to tell "it worked" from "you messed up" from "they messed up", and see why every app, agent and automation you'll ever build reaches the world the same way.

01 / 04

One request, one response, every time

An API — Application Programming Interface — is not a piece of software you install. It's a contract: a fixed, published way to ask one program to do something and get a predictable answer back. Think of a waiter. You never walk into the kitchen — you hand over an order and, moments later, a plate arrives. Press the button and watch one order travel to the kitchen and come back as a dish.

Here is the whole idea in one picture. Your app has a job it can't finish alone — say, showing today's weather for a city. It doesn't reinvent meteorology. It packages a small, standard request: which action it wants, the exact address to send it to, a key that proves it's allowed to ask, and the tiny bit of data the other side needs. That bundle flies off to the API. The API does the hard work behind a closed door and sends back a response — one tidy answer your app can use.

Notice what you don't see: how the kitchen cooks. That's the point of a contract. You don't need to know how the weather service measures temperature, only how to order and how the plate will look when it arrives. Press Send request and watch the pieces fly to the API and return as a single clean response.

Why "request and response" is the whole idea

Strip away the jargon and every API call is this: you ask, they answer. A request is your order — clear, structured, standard. A response is the plate — the answer plus a note saying whether it worked. You'll make thousands of these, and they all share this shape. Master the round trip and the rest of this week is just filling in what goes in the order and how to read what comes back.

02 / 04

JSON: labelled boxes of data

When the response comes back, it isn't a paragraph or a picture — it's JSON: a plain-text format of labelled boxes that both humans and programs can read. Almost every API speaks it. It looks intimidating for about five minutes, then becomes obvious. Flip each box below to see what it actually holds.

JSON is just keys and values: a label on the left, the thing it holds on the right, wrapped in braces { }. "city": "Mumbai" means "the key city holds the value Mumbai." That's the entire concept. The only thing left to learn is the four kinds of value JSON can hold — and once you can spot those on sight, you can read any response any API will ever send you. Flip the four boxes.

A boolean

Only true or false, no quotes. A yes/no switch your code can branch on: is it day, did payment succeed, is the account active. Two values, endless uses.

Array & object

Square brackets [ ] hold a list of things; curly braces { } hold a labelled group. Nest a list of objects inside a key and JSON can describe almost anything — a whole conversation, a week of forecasts.

The plain-English rule for reading JSON

You don't memorise JSON — you scan it. Find the key you care about, read the value beside it, and check its type by sight: quotes = text, no quotes = number or true/false, brackets = a list, braces = a group. That's the whole skill. Every AI API you call this week hands back its answer in exactly this shape, and pulling the one field you need out of it is the single most common thing you'll do with an API.

03 / 04

Endpoint, method, status code

Three words unlock most of the API vocabulary you'll ever meet. The endpoint is where you're calling. The method is what you want done. The status code is the API telling you whether it worked — and, crucially, whose fault it is when it didn't. Click through each.

Keep the honest framing from earlier weeks: an API is a tool with clear rules, not a mind-reader. It does exactly what its contract says — no more, no less. So when a call fails, it's almost never mysterious; it's one of a handful of named reasons, and the status code names it for you. Walk the four parts below, then read a status code like someone who's done it a hundred times.

Reading a status code like a pro

The first digit tells you the story. 2xx means it worked — the answer is attached, go use it. 4xx means you made a mistake — wrong key, wrong address, missing field; fix your request and it'll work. 5xx means they made a mistake — the API broke on its own end; your request was fine, so wait and retry. Learn to glance at that number before the data, and you'll debug an API call in seconds instead of an afternoon.

04 / 04

Everything connects through APIs

Once you see APIs, you see them everywhere. Every app on your phone, every AI agent, every automation you built last week — none of them work alone. They all reach out to APIs for the things they don't do themselves. Move the sliders and feel why nobody builds it all from scratch.

Here's the shift in how you'll think from now on. When your project needs a capability — weather, maps, payments, sending email, or a large language model's intelligence — your first question is no longer "how do I build this?" It's "whose API already does this?" Someone has usually spent years perfecting that one thing behind a clean contract you can call in a single line. An app, an agent and an automation all reach that same contract the same way. Why this is the backbone of everything you'll build

You spent four weeks learning to think in prompts, tools and automations. Every one of those talks to the outside world through APIs — it's the universal joint that lets small pieces connect into something big. This week you learn to call them yourself, and the very next lesson is the one that matters most: how to call an AI API, so your app can borrow a model's intelligence on demand.

What to carry forward

An API is a contract — a fixed, published way to ask one program for something and get a predictable answer back. Every call is a round trip: your app sends a structured request, the API sends a structured response, usually in JSON. Learn to read that JSON, glance at the status code to see whose fault a failure is, and you can wire your project into almost any capability on the internet without building it yourself.

  • API = a contract: a standard way to ask a program for something and get an answer
  • Every call is a round trip — a request goes out, a response comes back
  • JSON = labelled boxes: quotes are text, no quotes are numbers or true/false, brackets are lists
  • Endpoint = where · Method = what · Status code = did it work (2xx / 4xx you / 5xx them)
  • Apps, agents and automations all reach the world the same way: through APIs
