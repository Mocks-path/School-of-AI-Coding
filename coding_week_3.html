Beat One · What Is an Agent

The Job a Script Can't Do — Meet the Agent

Before Maya builds anything, one realisation reframes the whole week: her old tools follow steps she writes down in advance. This new job has no fixed steps. Understanding why that needs an agent — and where an agent would be overkill — is the first beat.

📖 The story so far Monday, 7:40 a.m. Maya opens her laptop and there they are again: 14 overnight messages. A helper asking to swap a Saturday. Two people asking if the fig & cedar candle is back. Someone asking about a bulk order for an office. A supplier note. A "just checking you got my last email?" She's spent an hour on this every morning for months. Her instinct from Week 1 kicks in — write a script. Then she stops: a script needs me to know the steps in advance, and these messages are never the same twice. This isn't a script problem. It might be her first agent.
📜
Fixed steps · Rock-solid, rigid

A script / fixed workflow

Like ReceiptTidy: you write the exact steps once, and it runs them the same way every time. Perfect when the task is identical each run — brittle the moment reality varies from the plan you wrote.

🤖
A goal + a loop · Adapts

An AI agent

A model given a goal, some tools, and a loop: it reads the situation, decides the next step, does it, checks the result, and repeats. It handles jobs where the steps change — but it needs guardrails, because it decides.

Beat Two · Design the Job

The Brief Comes First — Goal, Tools, Guardrails

An agent is only as good as the job you hand it. Before building, Maya writes a one-page brief: the goal and what "done well" means, the tools it may use, the role and house rules, and — most important — what it may do on its own vs. what needs her approval. A vague brief makes a vague, wandering agent.

📖 The story so far Tuesday evening. Maya has decided: this job is worth an agent. But she remembers the lesson from ShiftSwap — design is cheap on paper and expensive later. So before she opens any builder, she writes InboxScout's brief. The same agent can be a careful assistant or a loose cannon depending entirely on how tightly she scopes it. Flip between three versions of the brief below and watch the agent's whole personality change.
📄 inboxscout / brief.md
🤖
InboxScoutAgent brief · draft
Goal: every morning, sort the overnight inbox and draft replies to the routine ones — never send without Maya's OK.
Tools: read inbox, search my notes & FAQ doc, check my calendar, write a draft. Success: routine messages get an accurate draft; anything unusual is flagged for me. Boundaries: never sends, never touches money, never invents an answer — if unsure, it says so and asks.
Scope: narrow · Autonomy: draft-only · Approval: before any send
"Goal: help me with my email. Tools: whatever it needs. It can go ahead and do anything that saves me time."
← This is a wish, not a brief. No definition of "done," no boundaries, and "do anything that saves time" is exactly how an agent ends up sending a confident wrong reply at 2 a.m. Vague brief in, unpredictable agent out.
"Goal: each morning, label the overnight inbox and draft replies to routine messages; flag anything unusual for me. Tools: read inbox, search my notes/FAQ, check calendar, write a draft. Never send without my approval. If it isn't sure, it says 'I don't know' and asks — it never guesses."
← Same job. The difference is the brief: a concrete goal, a named tool list, a clear line between draft (allowed) and send (needs Maya), and an honest rule for uncertainty. This is what you design before you build anything.

Maya's design checklist

  • Write the  goal  and what "done well" looks like (success criteria)
  • List the  tools  it may use — read inbox, search notes, check calendar, draft
  • Write the role + instructions (who it is, its house rules)
  • Set the guardrails (never send unasked, never touch money, no guessing)
  • Decide autonomous vs. approval for each kind of action
  • Write it all as a one-page brief you could hand to anyone
✅ InboxScout's brief is written. One page: goal, tools, role, guardrails, approval rules. Maya hasn't built a thing yet — and that's exactly why the build will go fast. Onto the workbench.

🎚️ The Autonomy Dial — what may it do alone?

The single most important design choice: not what can the agent do, but what may it do without asking you first. The rule of thumb — let it act alone on cheap, reversible things; keep a human on anything costly or impossible to undo. Pick an action and see where it lands.

💡 Autonomy isn't all-or-nothing — you set it action by action. A draft is a suggestion you can bin; a sent email can't be un-sent. Start tight: let it act alone only where a mistake is cheap and reversible, and widen the leash later once it's earned trust.

Beat Three · Build It

One Tool at a Time — and Read the Reasoning Trace

Now Maya builds — but not all at once. She picks a low-friction approach, adds one tool at a time, and tests after each. The superpower here is the reasoning trace: the agent shows its thinking and every tool it calls, so when it misbehaves — wrong tool, endless loop, an invented answer — you can see exactly where and fix it.

📖 The story so far Wednesday. Maya opens an agent builder — the kind where you write the brief in plain language and wire in tools without installing anything. She resists giving it all four tools at once. Instead: read the inbox first, test, then add search, test, then calendar, then draft. After each tool she runs it on yesterday's real messages and reads the trace line by line. Because that's the whole game now — an agent that can't be watched can't be trusted. 🔬 Read the trace — good step or bug?

For each step InboxScout takes, decide: ship it (the behaviour is correct) or debug it (something's wrong and needs fixing). Reading the trace like this is the skill of building an agent.

Beat Four · Evaluate, Trust & Ship

Reliability Is Measured, Not Assumed — Then You Ship Narrow

An agent that worked once hasn't earned your trust. Maya runs InboxScout many times, counts how often it's right, hunts for the silent wrong answers, adds the guardrail that fixes the worst failure, and only then ships — narrow, documented, and with a human on anything irreversible. "It looked fine" is not evidence.

📖 The story so far Thursday. InboxScout runs. But Maya doesn't hand it the keys because one demo went well — she remembers that a build that works for you isn't shipped. So she runs it on 20 past mornings, tallies the results, and reads every draft looking for the dangerous kind of failure: the answer that's wrong but confident, the one nobody would catch. Then she decides, for each behaviour, how much rope it gets. Play with the trust numbers first, then judge each behaviour.

InboxScout ships — but on Maya's terms. It labels and drafts on its own, because that's cheap and reversible. It never sends without her nod, because that can't be undone. That's the difference between hype and a shipped agent. 🎉

The Honest Beat

Hype vs Durable — What an Agent Actually Is

Before you celebrate, the slide most courses skip. The internet is loud with "fully autonomous AI employees." Know exactly what agents genuinely changed — and what they never will.

⚖️ The Durable / Hype Split

Build your instincts on the left column. Ignore anyone selling you the right one.

✓ What agents genuinely changed
  • A recurring, multi-step job can now run without you doing each step
  • The model can use tools and act, not just chat back
  • It can reason through steps you never scripted in advance
  • One person can hand off real work — and read the trace to check it
✕ What agents did NOT change (the hype)
  • They still fail — often silently and confidently
  • "Fully autonomous employee, zero oversight" is marketing, not reality
  • A vague goal still produces a vague, wandering agent
  • Nothing replaces your judgment on the risky, irreversible call

🎉 On Monday, the inbox owned Maya's mornings.

By Thursday she'd handed that hour to InboxScout — an agent she designed, built one tool at a time, tested 20 ways, and shipped with a human on the risky moves. Here's what the story secretly taught you: the four lessons of Week 3.

Lesson 1

What Is an Agent

A model + tools + a loop + a goal. It shines when the steps vary each time — and is overkill when a fixed script would do. Beat 1.

Lesson 2

Design the Job

Write the brief before you build: goal, success, tools, role, guardrails — and the line between what it may do alone and what needs you. Beat 2.

Lesson 3

Build It

Add one tool at a time, test after each, and read the reasoning trace so you can catch the wrong tool, the loop, the invented answer. Beat 3.

Lesson 4

Evaluate, Trust & Ship

Measure reliability across many runs, hunt the silent wrong answer, add the guardrail, keep a human on the irreversible — ship narrow. Beat 4.

InboxScout is a teaching scenario. Real agents vary widely and most take several rounds of testing before they're trustworthy — the goal of Week 3 is to walk every beat once so your first agent starts as a builder's, not a gambler's. An agent is leverage, not magic; it gives a careful person real time back, never a careless one a free pass.
