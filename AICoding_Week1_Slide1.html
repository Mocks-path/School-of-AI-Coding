AI is the drafter. You close the loop: you run it, because running it is the only thing that proves it works. The run is the proof.

Concept 2 of 4

Specifying & Decomposition

AI confidently builds exactly what you asked for — a problem when you asked for the wrong thing. Vague in, vague out. The skill is turning a fuzzy wish into a precise spec, and breaking one big task into small, checkable steps.

Input, output, rules, edges — a real spec. The prompt is the spec. Write the spec well and the code mostly writes itself.
Same goal · Two prompts
Vague prompt "Make me a budget app." → a generic mess that doesn't fit your money, your categories, or your actual question.
Spec prompt · input + output + rules + edges "Read my transactions CSV. Group spending by category for last month. Output a table sorted high-to-low. If a row has no category, label it 'Uncategorized'. Ignore refunds (negative amounts)."
Concept 3 of 4

Reading & Debugging

You don't need to write code from a blank page — but you must be able to read it well enough to spot where it goes wrong. And it will. When it does, an error appears. Beginners panic; professionals lean in.

The error is not a wall — it's a clue. Read it, feed it back with context, isolate the smallest failing piece, and fix.
Three ways to face the same error
"It's broken. I give up — I'm not a coder."
panic · stuck
"Read the error → feed it back with context → isolate → fix"
clue · solved ✓
"Change random lines and hope it runs"
guessing · fragile

The error message is the most useful thing the computer can send you. Read it.

Concept 4 of 4

Trust & Verification

AI is confidently wrong in predictable ways: it invents libraries, writes silent security holes, and nails the happy path while ignoring the edge cases. None of these announce themselves — the code runs and looks fine.

AI can draft it. AI cannot be accountable for it. You own correctness — and that ownership is the whole job.

The Honest Slide

Most First Programs Break

The slide most courses skip. Anyone who says AI makes building effortless is selling you something.

Most

first programs break — on run one, probably run two. That's the normal texture of building software, not a sign you're bad at it.

The trap

"Vibe coding" — shipping code you don't understand because it seemed to work once. It fails without warning when the inputs change.

Your real goal

Not a masterpiece — one small program that works, that you understand, and that you've verified.

One small working, verified build is a real, honest win — and it's more than most people ever ship.
