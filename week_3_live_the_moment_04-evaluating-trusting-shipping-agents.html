Evaluating, Trusting & Shipping Agents — prove it works before you let it loose

Four hands-on activities. Build a mini eval and read an honest success rate, set the safety cap that catches loops and runaway cost, match each failure mode to the guardrail that stops it, and run the shipping-readiness checklist. "It worked once" is not the same as "I can trust it" — this lesson is the difference.

Build a mini eval — read the real success rate

An "eval" is just a small set of realistic test tasks you run the agent on — several times each, because an agent can answer the same task differently on different runs. The tasks: T1 summarize a note · T2 extract a date · T3 convert a currency amount · T4 look up a fact and cite it · T5 finish a 2-step task end-to-end. Notice: T5 failed 0/3, and T3 passed only 2/3 — it's flaky. A single run could easily have hidden both.

💡 Why run each task more than once? Agents aren't perfectly repeatable — the same task can pass one run and fail the next. One green run feels reassuring and proves almost nothing. A success rate across several runs is what tells you whether you can actually trust it.

Set the safety cap — enough to finish, tight enough to catch a loop

A step cap is a simple guardrail: the agent is allowed at most N steps before it must stop. Too low and it gets cut off before finishing real work; too high and a runaway loop can burn time and cost before anything halts. Slide to set the cap. 💡 Caps are cheap insurance: a step cap and a budget cap can't make an agent smarter, but they turn a worst-case runaway from "burned hours and a scary bill" into "stopped after N steps, ready to inspect." Set them a little above what a hard case honestly needs — no more.
