Week 5 · Lesson 02 · AI APIs

Borrow a model's intelligence, one call at a time.

Last lesson you learned the shape of every API call: a request goes out, a response comes back. Now we point that round trip at the most useful kind of API there is — one that hands you a large language model on demand. You don't run the model, host it, or train it. You send it a prompt and it sends back words. In this lesson you'll build an AI request part by part, pull the generated text out of the JSON that comes back, lock down the one thing that must never leak — your key — and put a real number on what all of this costs.

01 / 04

Four parts and a send button

An AI API request looks scary in a tutorial and turns out to be four small things plus a send. A key that proves it's you, a model that decides which brain answers, the messages that carry your prompt, and a few parameters that shape the reply. Click each part to see what it does — and what to leave alone.

Don't overthink this. Every request to a chat-style AI model is the same handful of fields, no matter the provider. Once you can name them, you can read any code sample and swap in your own prompt with confidence. The only field that is truly yours to craft is the messages — that's your Week 2 prompt-writing, finally talking to a model over the wire. Everything else is a dial you set once and mostly forget.

Click through the parts below. Notice how little of it changes call to call: the key, model and parameters usually stay put, and only the prompt inside messages moves.

The one part you actually write

Four of the five fields are boilerplate you copy once and reuse forever. The fifth — messages — is the whole game. It's where a vague ask ("write something about dogs") becomes a good one ("write a 40-word friendly intro for a dog-walking service, no emojis"). The model can only be as clear as your prompt. So the skill of calling an AI API is really the skill of writing the messages inside it well.

02 / 04

The answer is in the JSON — go get it

You send the request; a response comes back. But it isn't just the text you asked for — it's a JSON envelope with the text tucked inside, wrapped in metadata about the call. Learning to reach in and pull out the one field you want is the second half of every AI API call. Press generate and watch the envelope arrive.

Here's the thing that trips up every beginner. You ask the model to "write a haiku" and expect a haiku back. What you actually get is an object: an id, the model name, token counts, a finish reason — and, buried a couple of layers down, the haiku. That buried field is almost always at the same address: choices[0].message.content. Learn that one path and you can grab the generated text from any chat-style response. Press generate and watch the response assemble, field by field.

Parsing is just following the path. The generated text lives at choices[0].message.content — same address every time. Grab that one string, ignore the rest, and you have your answer.

Why the envelope matters

The metadata around your text isn't clutter — it's useful. finish tells you whether the reply was cut off (so you can raise max_tokens and retry). usage tells you exactly how many tokens the call cost, which is how you keep the bill honest. But when you just want the words, you reach for content. One path in, one string out. That's parsing.

03 / 04

The one rule you cannot break: keys stay on the server

Everything else in this lesson is a preference. This is a law. Your API key is a password to your account and your bill — and if it ever ships inside code that runs in someone's browser, it is already stolen. Watch what "in the browser" really means, and where the key belongs instead.

Here's the trap beginners fall into. It feels natural to call the AI API straight from your web page — the page needs the answer, so the page makes the request. But anything in a page is readable by anyone who opens it: the key sits right there in the source and the network tab, free for the taking. Within hours a stranger is spending your money and hitting your limits. The fix is simple and non-negotiable: the key lives on your server. The browser asks your server; your server, holding the key privately, calls the AI API. Press the button and move the key where it belongs.

The rule in one sentence

Never put an API key in anything that runs on someone else's device. If you can see the key by opening a browser's developer tools, so can everyone else. Keep it in an environment variable on a server you control, route your app's requests through that server, and rotate the key immediately the moment you suspect it slipped out. This single habit separates a safe project from a surprise bill.

04 / 04

Tokens are the meter — and you control it

AI APIs don't charge per request — they charge per token, the little chunks of text a model reads and writes (roughly ¾ of a word each). Longer prompt, more tokens. Longer reply, more tokens. More calls, more tokens. Move the sliders and watch a real bill take shape — and where the leaks are.

This is the number most beginners never look at until it surprises them. Every call is billed on the tokens going in (your prompt) plus the tokens coming out (the reply), and a busy app multiplies that by thousands of calls a day. The good news: you hold every lever. A tighter prompt, a capped max_tokens, a smaller model, and caching repeated answers each cut the meter directly. There's also a second limit that isn't about money — a rate limit, the cap on how many requests you may send per minute. How to keep the meter low

You just watched cost track length and volume. So the levers are obvious: cut the prompt to what the model truly needs, cap max_tokens so replies can't run away, pick the smallest model that does the job, and cache answers you'd otherwise ask for twice. And when your call volume climbs toward the rate limit, slow down or batch requests rather than hammering the API. Cost and limits aren't traps — they're dials, and now you know where they are. Next lesson, we put a whole AI API call to work inside something you build.

What to carry forward

Calling an AI API is four fields and a send: a secret key, a chosen model, the messages that carry your prompt, and a few parameters. The reply comes back as JSON, and the text you want is a fixed path away — choices[0].message.content. Keep the key on a server you control, never in a browser, and watch the token meter: cost tracks length and volume, and every part of that is a dial you can turn down.

  • An AI request = key + model + messages + parameters, sent to an endpoint
  • The messages carry your prompt — the one field you actually craft
  • The reply is JSON; pull the text from choices[0].message.content
  • Golden rule: keys live on your server, never in code the browser can read
  • You pay per token — shorter prompts, capped replies and caching cut the bill
