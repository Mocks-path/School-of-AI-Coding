Order the build loop — the rhythm that keeps you unstuck

Beginners get overwhelmed because they try to build the whole app at once. Experienced builders (and AI working with them) move in a tight, repeating loop: build one small piece, run it, look at it, fix what's off, save the working version, and only then move on. The seven steps below are shuffled. Click them in the order a calm builder follows — a wrong click shakes red and hints at what comes next.

Shuffled build-loop steps — click the next one

Your build loop, start to repeat

💡 Small steps, seen often: the whole point of the loop is that you never write more than you can run and check. When something breaks, only the last little change could be at fault — so it's easy to find. AI can generate a whole screen in seconds, but you still drive the loop: run it, look, and confirm each piece works before asking for the next.
2

Match the project to the right build approach

There isn't one "right" way to build an app — there's a right way for this project. A drag-and-drop no-code tool, an AI app builder, and a real code framework each fit different needs. Read what each project actually requires, then drag it to the approach that fits best. Choosing the lightest tool that can do the job is a skill on its own. Wrong answers carry a hover hint.

N

No-code / AI builder

Assemble screens by dragging blocks or describing them in plain language. Fastest path when the app is standard and simple.

  • Forms, simple databases, basic dashboards
  • No custom logic the tool can't express
  • Fewest moving parts, quickest to a demo
L

Low-code

A visual tool that lets you drop in small pieces of custom code when the standard blocks aren't quite enough.

  • Mostly standard, with a few special rules
  • Custom calculation, integration, or logic
  • More control than pure no-code
C

Code framework

Build with real code (AI writing most of it) for full control when the app is unusual or needs to grow.

  • Custom behavior no tool supports
  • Needs to scale or be maintained long-term
  • Most power, most responsibility
💡 Pick the lightest tool that fits: reaching for a full code framework when a no-code form would do wastes time; forcing an unusual app into a rigid no-code tool wastes even more. The durable skill is matching the approach to the actual requirements — not chasing whichever tool is trendiest.

Trace one click through the three layers

Almost every app has the same three layers: the UI (what the user sees and taps), the logic (the rules that decide what to do), and the data (what gets stored and read back). Picture a to-do app. A user types "Buy milk" and clicks Add. Click the step that belongs at each layer — the right ones snap into place; steps that belong to a different layer turn red and don't count.

What does this app need to remember? — the state quiz

An app's state is simply everything it has to remember while it's running: what the user typed, which tab is open, whether they're logged in. Getting state right is what separates an app that feels solid from one that forgets your work. Five real decisions, one best answer each — and every option comes with an explanation.

Quick reflect — make it stick

A sentence each is enough. Writing it in your own words is what moves it into memory. (Nothing is saved or sent.)

Think of a small app you'd like to build (a habit tracker, a tip calculator, a reading list). Name one thing at each layer: what the user sees (UI), one rule it follows (logic), and one thing it stores (data).
