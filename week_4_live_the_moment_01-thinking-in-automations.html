Order the flow — from "something happened" to "it's handled"

An automation is just a sentence: "when X happens, do Y." Every one is built from the same three parts — a trigger (the event that starts it), a condition (a yes/no check), and one or more actions (the work it does). The five steps below are a real automation, shuffled. Click them in the order they actually run — a wrong click shakes red and nudges you.

1

Trigger

The event that kicks things off — a form is submitted, a file lands, a time of day arrives. Nothing runs until the trigger fires.

+ One clear "start" you can point to − Pick a vague trigger and it fires at the wrong times
?

Condition

A yes/no check that decides whether to keep going — "is this actually a support request?" It's the filter that keeps the automation from acting on the wrong things.

+ Stops the flow doing work it shouldn't − Skip it and you spam yourself on every event
→

Action

The actual work — save a file, create a record, send a reply. Most automations chain a few actions in a row after the check passes.

+ This is the payoff — the task done for you − Order matters; a wrong sequence breaks things

Automate it, hand it to an agent, or keep it manual?

Not everything should be automated — and knowing the difference is the whole skill. A fixed automation shines on repetitive, rule-based, high-volume work. An agent earns its keep when the steps vary and need judgment. Some work should stay manual — rare, high-stakes, or too consequential to hand off. Drag each task to where it belongs. Guess freely; wrong pills carry a hover hint with the answer.

Automate it
Repetitive · rule-based · high-volume
Hand it to an agent
Varies each time · needs reasoning
Keep it manual
Rare · high-stakes · human judgment
💡 The honest truth about automation: the win isn't automating everything — it's automating the right things. Force a fixed automation onto judgment work and it makes confident mistakes at scale; keep a boring, repetitive task manual and you burn hours you'll never get back. Match the task to the tool first.
