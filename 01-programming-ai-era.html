Week 1 · Lesson 01 · AI Programming

Programming in the AI era.

Programming has always been one thing: turning a clear idea into instructions a computer will follow. That hasn't changed. What changed is who types the first draft. Today you can describe what you want in plain English and let an AI assistant write the code — while you stay the one who decides, tests, and fixes. This lesson gives you the honest map of that new working relationship before you write a single prompt.

01 / 04

What programming really is

Strip away the jargon and a program is just a recipe: a list of exact steps a computer runs, in order, without guessing what you meant. Programming is the act of writing that recipe clearly enough that a machine can follow it.

A computer is fast, tireless, and completely literal. It does exactly what the instructions say — not what you hoped they'd say. That's the whole difficulty and the whole power. Get the steps right and the machine repeats them perfectly a million times. Get one step wrong and it repeats the mistake a million times, just as cheerfully.

So every program is born the same way: an idea in a human head, translated into code (the exact written steps), which the machine turns into a running program that does something useful. Historically, a human wrote every line of that code by hand. "Coding with AI" changes only the middle step: you still own the idea and judge the result, but the AI drafts the code for you.

What "coding with AI" actually means

It does not mean the AI decides what to build or whether the result is correct. It means you write the idea in plain English, the AI drafts the code, and then you run it, read it, and steer it. You direct; the AI drafts. The skill you're really learning in this course isn't typing syntax from memory — it's describing problems precisely, reading what comes back, and knowing when it's wrong. Those skills outlast any single tool.

02 / 04

The loop that runs everything

Nobody — human or AI — writes a working program in one clean shot. Real coding is a loop you go around again and again until the result is right. Learn the loop and you can build almost anything with AI at your side.

The loop has six moves: Describe what you want, let the AI Generate a draft, Run it to see what actually happens, Read the code and the result to understand it, Fix what's wrong (usually by describing the problem again), and Repeat until it does the job. The first draft is almost never the final answer — and that's normal, not failure.

The move beginners skip is Read. It's tempting to paste code, see it run, and move on. But if you never read what the AI wrote, you can't tell a correct answer from a confident wrong one — and AI is very good at being confidently wrong. Press ▶ to watch one trip around the loop, step by step.

Who owns which move

Look at who acts at each stage. Describe, Read, and the decision to Fix or ship are all yours. Generate is the AI's — it drafts fast and cheap. Run belongs to the computer, which tells you the honest truth about whether the code works. AI generates; you decide. That division of labour is the heart of building software in the AI era: the machine does the typing, you do the judging.

03 / 04

How much do you actually type?

A fair question for a nervous beginner: if the AI writes the code, what's left for me? The honest answer is that the work shifts — away from typing syntax, toward describing, reading, and deciding. Drag the sliders and watch where the effort really goes.

Think of a small task — say, a script that renames a folder of photos by date. In the old world, most of your effort was recalling exact syntax: which punctuation, which function name, in which order. AI collapses that cost to near zero. But the other kinds of effort don't vanish — they grow in importance. You still have to describe the task clearly, read and verify what came back, and decide whether it's correct and safe to run.

The sliders below let you set how much effort each part takes for a given task. Notice the pattern: as "syntax recall" drops (which is what AI does for you), the share of your time spent on judgment — describing and verifying — goes up. That's the real shift AI makes. It doesn't remove the thinking; it moves the thinking to the front and the back.

The part AI can't take

Describing precisely is a skill. A vague request gets a vague program; the next lesson is entirely about this.
Reading is your safety net. AI is confidently wrong often enough that unread code is a liability, not a shortcut.
Deciding stays human. Whether the result is correct, safe, and actually solves your problem is a call only you can make — because only you know what "done" means.

04 / 04

A short history, and today's toolbox

The story of programming is one long march toward describing intent more like a human and less like a machine. AI assistants are the latest step, not a break from the past. First the history — then the categories of tools you'll actually meet.

Every generation of programming tools made the human's job more about ideas and less about machine detail. We went from flipping physical switches, to punch cards, to typed languages closer to English, to editors that autocomplete and catch mistakes — and now to assistants that draft whole chunks from a plain-English request. Each step didn't replace the programmer; it raised the level they work at.

Figure 4 · From punch cards to AI assistants
1940s–50s

Switches & punch cards

Instructions fed as holes in cardboard or physical wiring. One mistake meant re-punching a whole deck. The human worked at the machine's level.

1950s–70s

High-level languages

Languages like FORTRAN, and later C and Python, let people write steps in something closer to English and math. A translator turned it into machine code.

1990s–2010s

IDEs & smart editors

Editors autocompleted names, highlighted errors as you typed, and ran code with one click — catching mistakes before the machine ever saw them.

2020s–now

AI assistants

You describe intent in plain English and the assistant drafts working code. The human's job moves further toward directing, reading, and deciding.

Same loop, different rooms

Whichever category you pick, you're still running Describe → Generate → Run → Read → Fix → Repeat. The tools differ only in where the loop happens and how much they set up for you. A beginner can start with a chat assistant and a cloud sandbox — nothing to install — and graduate to an IDE copilot later. The skill transfers; the buttons don't matter.

What to carry forward

You now know what programming actually is and how the AI era changes it. A program is a literal recipe the machine follows; "coding with AI" means you describe the idea in plain English and the AI drafts the code, while you run, read, and decide. Every real build runs the same six-step loop, and AI's job is to generate — yours is to judge. Tools are just different rooms for the same loop.
