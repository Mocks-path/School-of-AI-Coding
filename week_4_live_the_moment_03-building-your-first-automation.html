Building Your First Automation — one step at a time, tested with real data

Four hands-on activities. Write a crisp instruction for an AI step, build a flow the safe way (one step, tested, then the next), pick the simplest tool that fits the job, and trace what a flow really does with a given input. No code required — just clear thinking.

1

Write an AI step the flow can actually rely on

Dropping an AI step into an automation is powerful — but the flow around it is dumb machinery that just passes text along. So the AI step needs four things spelled out: the exact input it reads, a clear instruction, the precise output format the next step expects, and a fallback for when it's unsure. For each slot, drag in the version that's specific — and skip the vague trap that reads fine to a human but leaves a machine guessing.

1

Input

Name the exact field the AI should read — not "the whole thing". Point at one piece of data.

2

Instruction

One clear task with named choices. "Classify as A, B, or C" beats "sort this out somehow".

3

Output format

The exact shape the next step needs. Pin it down: one word, lowercase, nothing else.

4

Fallback

What to do when unsure. A safe default beats letting the AI invent something new.

💡 The trap is vagueness that sounds friendly: "just figure out what matters" is a fine thing to say to a colleague and a terrible thing to hand a machine. The next step in the flow can only work with an exact shape of answer. Build the specific version below.

Your AI-step instruction

💡 Why the format line matters most: the flow after the AI step usually branches on an exact value ("if it equals billing…"). If the AI answers "This looks like a billing question!" instead of the single word billing, that branch silently never fires. Pin the format and the rest of the flow becomes predictable.

Build it the safe way — one step, tested, then the next

Beginners build the whole flow, hit "run", and get a wall of errors with no idea which step broke. Pros build in a tight loop: add one step, run it with real sample data, check the output, and only then add the next. The five moves below are shuffled — click them in the order a careful builder actually works. A wrong click nudges you.

Shuffled moves — click the next one

The build loop, in order

💡 The loop repeats: add → run with real data → check → add the next. Each new step is built on an output you've already seen and trust, so when something breaks you know it was the step you just added. Only when the whole chain passes on real data do you turn it on — carefully, and watching the first live runs.
3

Which tool fits? — simplest that does the job wins

Three broad kinds of tool handle almost everything: a simple connector (one trigger, one or two actions), a visual multi-step builder (branches, filters, several apps, an AI step — no code), and a code-capable tool (for logic the builder can't express). The skill isn't picking the fanciest — it's picking the simplest tool that fits. Judge each job.
